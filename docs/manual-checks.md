# 実機で確認する項目（手動確認の手順）

自動テスト（`npm test` / `npm run test:db` / `npm run test:e2e`）では確かめられない項目です。
v1.0.0 の時点で、ここに書いた項目は**まだ実機では確認していません**。導入前に、実際の端末で次の手順を行ってください。
結果は「確認日・端末・OS とブラウザの版・結果」をメモしておくと、次の版での比較に使えます。

## 1. Windows の日本語 IME（Microsoft IME）＋ Chrome / Edge

文章入力〈変換あり〉・実物のキーボード・3分・標準問題で行います。

1. 見本の最初の単語を、ひらがなで打ち、変換候補を出したまま（下線がある状態）で止める → 「ミス」が増えないこと。
2. わざと別の漢字を選んで Enter で確定する（例：「機関」の位置で「期間」）→ ミスが**2文字分**増え、赤い文字で示されること。
3. そのまま続きを正しく入力する → ミスが増えないこと。
4. Backspace で誤りを消す → ミスが増えないこと。正しく入力し直すと、最後まで完成して次の問題に進むこと。
5. 変換を確定する Enter を押した直後に、続けてもう一度 Enter を押す → 改行が入らず、問題が飛ばされないこと（見本に改行がない位置）。
6. 見本の「↵」の位置で Enter → 改行が入ること。
7. 数字を全角（IME オン）・半角のどちらで入力しても正しく判定されること。
8. ローマ字入力で IME をオンのまま打つ → 「日本語入力がオンになっているようです」と表示され、ミスに数えないこと。「半角/全角」キーでオフにすると打てること。
9. 英語配列のキーボード（または Windows の設定で英語配列に切り替え）で、ローマ字入力の `-` `,` `.` が正しく判定されること。

## 2. iPad Safari（iPadOS）

1. 「ホーム画面に追加」→ アイコンが桜打のアイコンで、名前が「桜打」になること。
2. ローマ字入力・**画面のキーをタップ**：キーを押しても**端末のソフトウェアキーボードが出ない**こと、ダブルタップで拡大されないこと。
3. 文章入力・画面のキーボード（端末の日本語入力）：日本語キーボード（ローマ字・かな・フリック）で変換・確定でき、変換中はミスにならず、確定で判定されること。
4. 予測変換の候補をタップして確定 → 1回だけ判定されること（二重にミスが増えないこと）。
5. Smart Keyboard など実物のキーボードを付けた場合：ローマ字入力・実物のキーボードで打てること。日本語入力がオンのときは警告が出ること。
6. 画面を縦・横に回転してもレイアウトが崩れないこと。

## 3. Android（Chrome）＋ Gboard

1. 文章入力で、Gboard の日本語入力で変換・確定して判定されること（Android は英語入力でも変換イベントが出ることがあります）。
2. ローマ字入力・画面のキーをタップで、ソフトウェアキーボードが出ないこと。

## 4. Surface（タッチとキーボードの両方）

1. キーボードを外した状態で「画面のキーをタップ」が使えること。
2. 記録が「実物のキーボード」と「画面入力」で分かれて表示されること（結果画面の前回比較・先生の画面の条件の選択）。

## 5. 共有端末での運用

1. 生徒でログイン → 練習 → 「終了してログアウト」→ ブラウザの戻るボタンで前の画面に戻っても、記録や名前が表示されないこと。
2. ログインしたまま15分操作しない → 14分ごろに警告、15分で自動ログアウトすること。
3. ログイン中に再読み込み → ログアウトした状態になること。
4. ログアウト後、Supabase のダッシュボード（Authentication → Users → その生徒）でセッションが終了していること（表示がある場合）。

## 6. 本物の Supabase での権限の確認

`npm run test:db` は、ローカルの PostgreSQL で Supabase を模擬したテストです。導入した本物の環境でも、次を確かめてください。

1. 生徒A・生徒B（別のクラス）、先生A（Aのクラス）、先生B（Bのクラス）を用意する。
2. 生徒Aでログインし、ブラウザの開発者ツールのコンソールで次を実行しても、生徒Bの記録が返らない（空の配列）こと：
   アプリの通信（Network）で `practice_results` へのリクエストの URL の `user_id` を生徒Bの ID に書き換えて再送しても、空になること。
3. 先生Aでログインし、`#/teacher/student/（生徒Bの内部ID）` を開くと「表示できません」になること。
4. 先生Aで、二段階認証をせずに（確認コードの画面で「やめる」）先生用の画面を開けないこと。
5. 生徒で `profiles` の `role` を `teacher` に書き換える PATCH を送っても拒否されること。
6. 同じ生徒の ID で、わざと6回続けてパスワードを間違える → 「しばらくログインできません」と表示されること（フックを有効にした場合）。

## 7. 保存失敗と再送（本物の通信）

1. 生徒でログインし、練習の終わる直前に端末の Wi-Fi を切る → 結果画面で「× 記録を保存できませんでした」と表示され、「保存しました」と出ないこと。
2. Wi-Fi を戻して「もう一度保存する」→「✓ 記録を保存しました」。先生の画面で記録が1件だけ増えていること（二重にならない）。
3. 保存できていない記録があるまま「終了してログアウト」を押すと、確認が出ること。

## 8. 表示

1. 教室のプロジェクター（1280×720 など）・タブレット・スマートフォンで、問題・入力位置・残り時間が見やすいこと。
2. 画面右上の「v1.0.0」がボタンや問題と重ならないこと。
3. 色の区別がつきにくい人でも、ミス（×・波線）、次のキー（▼・太い枠）、使う指（文字で表示）が分かること。

## 9. v1.0.2 で追加した項目

1. Windows の日本語 IME がオンのまま開始待ちの画面でスペースキーを押す → 変換に使われたスペースで開始しないこと。IME をオフにしてスペースキーで開始できること。
2. iPad・スマートフォンで「スタート」ボタンをタップして開始できること。文章入力では、開始後に入力欄にフォーカスが移り、端末のキーボードが出ること。
3. 問題数で練習（25問）を最後まで行い、結果画面に「25問完了」・かかった時間が出ること。ログインしている場合は「✓ 記録を保存しました」となり、先生の画面の履歴で「25問」として、時間制とは別の条件に分かれていること（データベースに v1.0.2 のマイグレーションを適用した後）。
4. 訓令式を選んだとき、ガイドが si・ti・tu などで表示され、shi・chi などで打っても正解になること。

## 10. v1.0.3 で追加した項目（練習の記録・成長グラフ）

自動テストはモックとローカルの PostgreSQL で行っています。次は実機・本物の環境で確認してください。

1. 学校の PC（Windows・Edge / Chrome）と iPad Safari で、ゲストで練習 → ブラウザを完全に閉じて開き直す → 「練習の記録」に残っていること。
2. iPad Safari のプライベートブラウズや、ブラウザの設定でサイトのデータを保存しない設定のとき、結果画面で「× この端末に記録できませんでした」と出て、アプリが止まらないこと。
3. 共用端末で、「ゲストの記録をすべて削除」で記録が消え、ほかのサイトのデータや設定が消えないこと。
4. Supabase を設定したあと、生徒 A で練習 → 別の端末で生徒 A としてログイン → 「練習の記録」に同じ記録とグラフが出ること。生徒 B でログインすると A の記録が出ないこと。
5. Supabase を設定したあと、先生の画面の生徒詳細で、新しいグラフ・一覧が表示されること。

## 11. v1.1.0 で追加した項目（検定モード）

自動テストは Chromium で行い、日本語入力の変換は Chromium の IME 入力（CDP）で再現しています。**実際の IME・実機では、まだ確認していません。** 次を実機で確認してください。

1. **Surface・Windows の Edge / Chrome（Microsoft IME）**：検定モードで、ひらがなを入力して変換・確定・再変換・Backspace での削除が自然にできること。変換中に Space（次の候補）・Enter（確定）を押しても、アプリが開始・終了などの操作をしないこと。変換中は上部の「入力 ○文字」が増えず、確定すると増えること。
2. 開始前（待機画面）に IME がオンのまま Space を押す → 開始しない（変換に使われる）こと。IME をオフにして Space、またはスタートボタンで開始し、入力欄にカーソルが移ること。開始のスペースが本文に入らないこと。
3. 変換中（下線がある状態）のまま時間になる → 結果の入力文字数に変換中の文字が入らないこと。そのあと Enter を押しても結果が変わらないこと。
4. 練習中に別のタブ・別のアプリに切り替え、制限時間を過ぎてから戻る → すぐに締め切られ、経過時間が制限時間ちょうどになること。
5. 長い文章（1級相当）を入力しても、用紙の下で切れずにスクロールできること。左右が別々にスクロールできること。文字の大きさの変更で、お手本・用紙の両方が変わること。
6. iPad Safari：日本語キーボード（ローマ字・かな・フリック）で入力・変換でき、予測変換の候補を選んでも文字数が正しいこと。画面を縦にすると、お手本と用紙が上下に並ぶこと。
7. iPad・スマートフォンで撮影したプリントの写真（JPEG）を登録し、拡大・回転・ドラッグ（指ではスクロール）で読めること。iPhone の HEIC の写真を選ぶと、変換が必要という案内が出ること。
8. 学校で使う PDF（複数ページ・スキャンした PDF・文字情報のある PDF）を登録し、ページの選択・順番・表示・文字の取り出しができること。スキャンした PDF では「取り出せませんでした」と表示されること。
9. 教材パックを書き出し、別の生徒用端末（別の PC・iPad）で読み込んで、同じ問題・お手本・正解文で練習できること。同じパックをもう一度読み込んでも、問題が重複・上書きされないこと。
10. 端末の空き容量が少ないとき・プライベートブラウズのとき、保存できない旨の案内が出て、アプリが止まらないこと。
11. Supabase を設定したあと、`20261008000000_exam_results.sql` を適用し、生徒で検定モードを練習 →「✓ 記録を保存しました」→ 別の端末で同じ生徒として「練習の記録 → 検定モードの記録」に出ること。担当の先生の生徒詳細に出ること、担当外の先生には出ないこと。
12. Supabase を設定したあと、生徒でログインすると「先生の追加問題を管理する」が表示されないこと、先生でログインすると表示されること。

## 12. v1.2.0 で追加した項目（ゲームモード）

自動テストは Chromium（PC・タブレット・スマートフォンの画面幅）と、Supabase の通信のモック、ローカルの PostgreSQL で行っています。**実機・本物の Supabase では、まだ確認していません。**

1. Surface（1366×768 など）の Edge / Chrome で、建物の画像・工事の進み具合（ゲージ・完成率・残り文字数・工程名）・入力する文・次のキーが、スクロールしなくても見えること。キーボードと指のガイドが見やすいこと。
2. 日本語入力（Microsoft IME）がオンのまま打つ → 「日本語入力がオンになっているようです」と表示され、ミスに数えないこと。Caps Lock がオンでも打てること。
3. 開始の前に、設定のボタンなどを操作してからスペースを押しても、意図しない開始・ミスにならないこと。
4. 一時停止 → 休み時間ほど待つ → 再開 で、入力時間に一時停止の間が含まれないこと。一時停止せずに別のタブに切り替えたときは、時間が進むこと。
5. 標準コースを最後まで遊び、工程が 準備 → 基礎工事 → 壁の建築 → 本体の建築 → 塔の建築 → 完成 と進み、途中で黒い画面や読み込み待ちが出ないこと。画像の切り替えで、建物の位置の小さな違いが気にならないこと。完成の画面が大きく表示され、花びらの演出が控えめであること。
6. Windows の「アニメーションを表示する」をオフ（動きを減らす設定）にして、演出が止まること。
7. iPad・スマートフォンで「画面のキーをタップ」で遊べること。画面を縦・横にしても使えること。
8. Supabase を設定したあと、`20261009000000_game_results.sql` を適用し、生徒で遊ぶ →「✓ 記録をアカウントに保存しました」→ 別の端末で同じ生徒として「練習の記録 → ゲームの記録」に出ること。2回目に前回・自己ベストと比べられること。担当の先生の生徒詳細に出ること、担当外の先生・ほかの生徒には出ないこと。
9. 通信を切ってから完成させる → 「クラウドに保存できていません」と表示され、通信を戻して「もう一度保存する」で1件だけ保存されること。
10. 公開先（https://twataru0129-dot.github.io/sakurada/）で、画像が表示され、ゲーム・タイピング・検定・ログイン・記録の画面に移動できること。

## 13. v1.3.0 で変更した項目（ゲームの改善）

自動テストは Chromium の 1366×768・1280×720・スマートフォン幅で行っています。**実機では、まだ確認していません。**

1. Surface の Edge / Chrome（ズーム100％・ブラウザの通常の表示）で、ゲーム中に縦スクロールなしで、建物・入力する文・読み／ローマ字・工事の進み具合・時間とミス・一時停止・キーボードと指のガイドが見えること。ブックマークバーなどで表示領域が狭いときも確認してください。
2. 文が変わるとき・ミスを続けたときに、画面が跳ねたり、次のキーが見えなくなったりしないこと。
3. 音を ON にしてミスすると短い音が鳴ること。音を OFF にすると鳴らないこと。教室のスピーカーで大きすぎないこと。
4. 「アニメーションを表示する」をオフにしたとき、ミスの表示が動かないこと。
5. 短縮コース（約950打鍵）を最後まで遊び、完成すること。v1.2.0 で遊んだ短縮コースの記録が「旧短縮コース（約50打鍵）」として残っていること。
6. 完成記念画像：PC で PNG が保存できること（Edge・Chrome のダウンロード）。iPhone・iPad の Safari で「共有・写真に保存」または画像の長押しで写真に保存できること。ニックネームあり・なし、長い名前で文字が切れないこと。
7. 公開先（GitHub Pages のサブパス）で、建物の画像と完成記念画像が表示・保存できること。
8. Supabase を使う場合は `20261010000000_game_short_stories_v2.sql` を適用し、ログイン利用者の新しい短縮コースの記録が保存されること。

## 14. v1.3.1 で変更した項目（ゲームのプレイ画面の配置）

自動テストは Chromium の 1366×768・1280×720・1920×1080・スマートフォン幅（390×844・375×667・横向き 844×390）で行っています。**実機では、まだ確認していません。**

1. Surface の Edge / Chrome（ズーム100％）で、建物の画像と入力する文の枠が同じ大きさで左右に並び、その下にキーボード、すぐ下に指のガイドが、縦スクロールなしで見えること。ブックマークバーなどで表示領域が狭いときも確認してください。
2. いちばん長い文（「案内を読み、この教会の工事が千八百八十二年に始まったと知りました。」など）で、読み・ローマ字が枠からはみ出さず、文字が小さすぎないこと。教室の後ろの席からも読めること。
3. 読みとローマ字の改行位置がそろっていること。改行の位置で Enter やスペースを打たなくても次に進むこと。入力の途中で改行や枠の高さが変わらないこと。
4. si・ti・tu・zi、nn など別の打ち方で入力したとき、次の文字・光るキー・使う指が合っていること。
5. キーボードに必要なキーが欠けたり重なったりしていないこと。F・J の印が見えること。実物のキーボードの位置と見比べて違和感がないこと。
6. iPhone・iPad の Safari（縦向き・横向き）で、画面のキーをタップして入力でき、横にはみ出さず、キーが押しやすい大きさであること。
7. タイピングモード・検定モードのキーボードと画面が、v1.3.0 と変わっていないこと。
