# 安全のための設計と設定

## しくみ

| 項目 | 実装 |
|---|---|
| 認証 | Supabase Auth のパスワード認証を使います（パスワードは認証基盤がハッシュ化して保存。アプリは平文で保存しません） |
| メールを持たない生徒 | ID を内部用のアドレス `ID@id.sakura-type.invalid` に変換して認証基盤に登録します。メールは送りません。`.invalid` は実在しないドメインです |
| 新規登録 | 認証基盤の新規登録をオフにし、生徒は先生が Edge Function で発行します |
| 役割 | `profiles.role`（student / teacher）。画面・API からは変更できません（表の書き換え権限を与えていません）。教員は管理者が `npm run create-teacher` で作ります |
| 本人の記録だけ | データベースの RLS で `user_id = auth.uid()` を確認します |
| 教員は担当クラスだけ | RLS と SECURITY DEFINER 関数（`private.can_manage_student` など）で、担当クラスの生徒だけを対象にします。URL やリクエスト中の ID を書き換えても、担当外のデータは返りません |
| 教員の二段階認証 | TOTP（認証アプリ）。教員のデータ参照・管理は、データベースと Edge Function の両方で JWT の `aal2` を確認します |
| 管理用の鍵 | Edge Function の実行環境と、教員作成スクリプトを実行するターミナルだけで使います。フロントエンド・GitHub・配布ファイルには含めません |
| ログイン失敗の制限 | IP 単位：Supabase Auth の Rate limits。アカウント単位：Password Verification Attempt フック（15分以内に5回失敗で15分停止）。フックはプランによって使えない場合があります |
| 再送の重複防止 | 結果の ID を端末で作り、主キーにします。同じ結果を再送しても二重に登録されません |
| 入力値の検証 | 表示名・クラス名・教材は、画面とデータベースの両方で長さ・使える文字（`<` `>` と制御文字は不可）を確認します。画面では React がすべて文字として表示するため、入力した内容がスクリプトとして動くことはありません |
| 記録の値 | データベースのトリガーで速さ・正確率・ランク・正式かどうかを計算し直します。ありえない速さの記録、完走なのに時間が足りない記録は保存できません |
| 共有端末 | ログイン状態はメモリーだけに置き、ブラウザに保存しません。「終了してログアウト」で認証基盤のセッションを終了（`signOut`）し、画面上の記録と一時データを消します。無操作15分で自動ログアウト |
| 通信 | HTTPS（Supabase は HTTPS のみ。アプリの設定も https:// 以外を受け付けません。開発用の localhost を除く） |
| ログ | Edge Function のログには操作の種類と内部 ID だけを出し、パスワードは出しません |

- 検定モードの記録（`exam_results`）も、本人だけが追加・閲覧、担当の先生（二段階認証済み）だけが閲覧でき、変更・削除はできません。得点文字数と目安達成はデータベース側で計算し直し、値の整合性を制約で確かめます。入力した文章・正解文は保存しません。
- 検定モードの教材パックには、問題の設定・正解文・お手本のファイルだけを入れ、成績・入力本文・ログイン情報・認証情報は入れません。読み込むときは形式・容量・参照・照合値・重複 ID を確かめ、既存の問題を上書きしません。PDF の中のスクリプトは実行しません。

- ゲームモードの記録（`game_results`）も、本人だけが追加・閲覧、担当の先生（二段階認証済み）だけが閲覧でき、変更・削除はできません。ミス加算・記録タイム・完成年・正確率はデータベース側で計算し直し、物語と読みの文字数の整合性を確かめます。自己ベストの関数 `game_bests` は security invoker で、呼び出した人が見られる記録だけが対象です。入力した文章・打鍵の記録は保存しません。

## 残る注意点（正直に書いておくこと）

- ゲームの入力時間・ミス回数・正しい打鍵数は、端末で数えた値を受け取ります（範囲・速さの上限・物語との整合性は検証しますが、作り替えた値を完全には見分けられません）。

- **検定モードの先生の追加問題は、端末のブラウザ（IndexedDB）に保存します。** 管理画面を先生だけに表示するのは画面の制御で、クラウド上の権限の制御ではありません。端末を操作できる人は、技術的には端末内の問題を変更できます。また、教材パックは暗号化しないため、正解文はファイルを開けば読めます（配布は校内の範囲で行ってください）。
- 検定モードのミス数・一致した文字数は、正解文がデータベースにないため、端末で計算した値を受け取ります（範囲・組み合わせは検証しますが、作り替えた値を完全には見分けられません）。

- **「完全に安全」なしくみではありません。** 次の点を理解したうえで運用してください。
- 練習の数値（正しい数・ミス数）は端末で数えて送ります。サーバー側では計算のし直しと、ありえない値の拒否をしていますが、技術に詳しい人がブラウザの通信を改ざんすれば、もっともらしい数値を送ることはできます。成績評価に使うときは、授業中の様子とあわせて見てください。
- ログアウトすると認証基盤のセッションは終了しますが、すでに発行されたアクセストークン（JWT）は有効期限まで技術的には有効です。JWT の有効期間を15分程度に短くしてください（setup.md）。
- 無操作15分の自動ログアウトはブラウザで行います。サーバー側の無操作タイムアウトは Supabase の有料プランの機能です。
- アカウント単位のログイン失敗制限（フック）が使えないプランでは、IP 単位の制限だけになります。学校では同じ IP を共有するため、生徒のパスワードは推測されにくいもの（自動作成）にしてください。
- Supabase の管理者（ダッシュボードにログインできる人）は全データを見られます。管理者のアカウントにも二段階認証を設定してください。
- 生徒の ID・表示名はクラウドに保存されます。表示名には本名を使わないよう指導してください。
