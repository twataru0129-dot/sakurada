# 桜打 — SAKURA TYPE（v1.5.2）

特別支援学校高等部の情報の授業で使う、日本語タイピング学習アプリです。
ローマ字の習得から、正確さ・速さの向上、漢字変換を含む文章入力までを練習できます。
学校の PC、Surface、ノート PC、iPad、スマートフォンのブラウザで動きます。

## 1. 使える段階は2つあります

| 段階 | できること | 必要な準備 |
|---|---|---|
| **① ゲストで練習** | タイピングモード（ローマ字入力・文章入力〈変換あり〉）、ガイド、結果表示、**練習の記録と成長グラフ（この端末・ブラウザに最新100回分を保存）**、**検定モード（収録30問・先生の追加問題・教材パック）**、**ゲームモード（サクラダファミリアを完成させよ・桜ガーデン）** | **なし**（このリポジトリをビルドして置くだけ。外部サービスの設定は不要） |
| **② ログインして練習** | ①に加えて、ID とパスワードでのログイン、記録と設定のクラウド保存（どの端末からでも続きができる）、先生用の画面（クラス・生徒・教材の管理、成長グラフ） | Supabase（認証とデータベースのサービス）の設定。[docs/setup.md](docs/setup.md) の手順で行います |

> **大切**：②の設定をしていない状態では、入口の「ログインして練習」は押せず、「ログイン機能はまだ設定されていません」と表示されます。
> 設定前にログインや記録の保存ができるように見せることはありません。

この版でのモード：

- ① **タイピングモード**：使えます
- ② **ゲームモード**：使えます（v1.2.0）。ゲームの選択画面から「サクラダファミリアを完成させよ」で遊べます。物語をローマ字で入力すると建築が進み、最後まで打つと必ず完成します。時間制限・ゲームオーバーはありません。くわしくは [docs/game.md](docs/game.md)。
  v1.4.0 で「桜ガーデン」を追加しました。短い文章を打って水と花びらを集め、桜を育てて自分の庭を作ります。くわしくは [docs/garden.md](docs/garden.md)。
  v1.5.0 で「ボウイの爆弾遊戯」を追加しました。ボウイが投げる爆弾を、表示された文字を入力して解除します（全80問・被弾でその場で終了）。くわしくは [docs/bowie.md](docs/bowie.md)。
- ③ **検定モード**：使えます（v1.1.0）。お手本を見ながら白紙の A4 用紙に日本語の文章を入力します。収録問題30問（4級相当〜1級相当・各5問）、先生が画像・PDF で問題を追加でき、教材パックで別の端末へ配布できます。くわしくは [docs/exam.md](docs/exam.md)。
  日本語ワープロ検定の速度分野を参考にした桜打独自の練習で、採点は独自の規則です。公式検定の合格を認定するものではありません。

## 2. まずゲストで動かしてみる（先生の PC で）

1. [Node.js](https://nodejs.org/ja)（バージョン 22 以上）をインストールします。
2. このフォルダーで、ターミナル（Windows では「ターミナル」または「PowerShell」）を開き、次を順に入力します。

   ```
   npm install
   npm run dev
   ```

3. 表示された `http://localhost:5173/` をブラウザで開き、「ゲストで練習」を押します。

学校のサーバーなどに置くとき（公開）：

```
npm run build
```

できた `dist` フォルダーの中身を、Web サーバーの好きな場所（例：`https://学校のサーバー/typing/`）にそのままコピーします。
画像・マニフェストは相対パスで参照し、画面の切り替えは `#/home` のようなハッシュで行うため、**サブディレクトリに置いても動きます**（サーバーの書き換え設定は不要です）。
公開は **HTTPS** で行ってください。

### GitHub Pages で公開する（このリポジトリの設定）

`.github/workflows/deploy-pages.yml` が、main に push されるたびに `npm ci` → `npm test` → `npm run build` を行い、**`dist` の中身だけ**を公開します。
リポジトリの **Settings → Pages → Build and deployment → Source** を **「GitHub Actions」** にしてください。
「Deploy from a branch」のままだと、ビルド前の `index.html`（`/src/main.tsx` を読み込もうとする）がそのまま公開され、白い画面になります。

公開 URL：https://twataru0129-dot.github.io/sakurada/

ログインを使う場合は、Settings → Secrets and variables → Actions → **Variables** に `VITE_SUPABASE_URL`・`VITE_SUPABASE_ANON_KEY`（公開用キー）を登録し、Actions の「Deploy to GitHub Pages」を再実行します。未登録ならゲスト版として公開されます。service_role / secret キーは登録しないでください。

> オフライン対応（電波がない場所での利用）はしていません。アイコン（ホーム画面に追加）の設定は、オフライン対応を意味しません。

## 3. ログインと記録の保存を使う（クラウドの設定）

次の順で進めます。くわしい手順は [docs/setup.md](docs/setup.md) にあります。

1. Supabase のプロジェクトを作る
2. データベースの表と権限設定（`supabase/migrations/` の SQL）を入れる
3. 認証の安全設定をする（新規登録を止める、二段階認証、ログイン失敗の制限など）
4. 管理用の Edge Function（`supabase/functions/teacher-admin`）を登録する
5. `.env.example` をコピーして `.env.local` を作り、URL と公開用キーを書いてビルドし直す
6. **最初の教員アカウント**を作る（下の 4.）
7. 先生がログインして、二段階認証を登録し、クラスと生徒のアカウントを作る（下の 5.）

---

## 4. 最初の教員アカウントを作る

教員アカウントは、画面からは作れません（生徒が教員の権限を得られないようにするためです）。
管理者が自分の PC で次を実行します。管理用の鍵（service_role / secret キー）は**ファイルに保存せず**、その場だけ入力します。

Windows（PowerShell）：

```
$env:SUPABASE_URL="https://（プロジェクト）.supabase.co"
$env:SUPABASE_SERVICE_ROLE_KEY="（管理用の鍵）"
npm run create-teacher
```

Mac / Linux：

```
SUPABASE_URL="https://（プロジェクト）.supabase.co" SUPABASE_SERVICE_ROLE_KEY="（管理用の鍵）" npm run create-teacher
```

ID・表示名・パスワード（画面に表示されません）を聞かれるので入力します。2人目以降の先生も同じ方法で作ります。
終わったらターミナルを閉じてください（鍵が残らないようにします）。

作った先生がアプリでログインすると、**二段階認証（認証アプリ）の登録画面**が出ます。スマートフォンの認証アプリ（Google Authenticator、Microsoft Authenticator など）で QR コードを読み取り、6けたのコードを入力します。
認証アプリの端末をなくしたときは、管理者が次を実行して登録を解除します（次のログインで登録し直し）：

```
npm run create-teacher -- --reset-mfa 先生のID
```

## 5. 生徒のアカウントを発行する

生徒による自由な新規登録はありません。先生が発行します。メールアドレスや本名は登録しません。

1. 「ログインして練習」→ 先生の ID・パスワード → 確認コードでログインします。
2. 「先生用の画面」→「クラスと生徒」で、**クラスを作成**します（例：1年A組 情報）。
3. 「生徒のアカウントを発行」で、ID（例：`sakura01`）、表示名（ハンドルネーム）、初期パスワード（「自動で作る」が便利）を入れて「発行する」。
4. 表示された ID とパスワードを生徒に伝えたら「閉じる」を押します。**パスワードはこのあと誰も見られません**（先生も再設定だけができます）。
5. パスワードを忘れた生徒は、生徒の「くわしく・管理」→「パスワードを再設定」で新しいパスワードを作ります（前のパスワードやほかの生徒と同じパスワードは使わないでください）。

ほかに、生徒ごとの初期設定（練習時間・難易度・ガイド）、表示名の変更、クラスの所属、アカウントの停止・削除、練習履歴と成長グラフの確認、追加教材の登録ができます。
くわしくは [docs/teacher-guide.md](docs/teacher-guide.md)。

## 6. 保存する情報と目的（生徒・保護者への説明にも使えます）

ログインした人について、次のものだけをクラウド（Supabase）に保存します。

- 内部のユーザー番号、ID、表示名（ハンドルネーム）、役割（生徒／先生）、クラス
- 学習設定（ガイドの ON/OFF、音、練習時間、難易度）
- 練習ごとに：日時、練習の種類・テーマ・難易度、問題セットとランク基準の版、練習時間、完走か途中終了か、入力のしかた、正しく入力した数、ミスの数、正確率、速さ、ランク

- ゲームモードのプレイごとに（別の表 `game_results`）：日時、ゲーム・ルール・物語の版、物語、コース、入力のしかた、ローマ字のお手本、入力時間、ミス回数、ミス加算・記録タイム・ゲーム内の完成年・正確率、正しく打ったキーの数、読みの文字数（入力した数／全体）、一時停止の回数、完成したか
- 桜ガーデンの記録（別の表 `garden_events`）：問題の完成（練習の番号・何問目か・問題の番号）、水やり・苗や飾りとの交換・植える／置く・片付け・庭の名前・問題数の設定と、それぞれの日時
- 検定モードの練習ごとに（タイピングの記録とは別の表）：日時、問題の ID・名前・改訂番号・段階、時間の設定と経過時間、終わりかた、自動採点の有無、入力文字数、一致した文字数、ミス数、得点文字数、目安達成の有無

**保存しないもの**：生徒が入力した文章そのもの（検定モードの入力本文も含む）、ゲームの打鍵の記録、1つ1つのキー操作の履歴、メールアドレス、本名。
先生が検定モードに追加した問題（画像・PDF・正解文）は、その端末のブラウザに保存し、クラウドには送りません（配布は教材パックのファイルで行います）。
文章の照合は端末の中で行い、集計した数だけを送ります。
目的は、本人が成長を確かめること、担当の先生が授業で様子を知ることです。記録を見られるのは本人と、そのクラスを担当する先生だけです（データベースの権限設定で確認しています）。

ゲストの記録は、この端末・ブラウザ（localStorage）に最新100回分を保存します（桜ガーデンの庭は、この端末に別に保存します）。クラウドには送らず、ほかの端末・ブラウザには引き継がれません。ブラウザのデータを削除すると消えます。共用端末では、ほかの人の記録も表示される場合があります。「練習の記録」の画面の「ゲストの記録をすべて削除」で消せます。ログインしても、ゲストの記録はアカウントへ移しません。

共有の端末では、終わったら必ず「終了してログアウト」を押します。15分間操作がないと自動でログアウトします。ログイン状態はブラウザに保存しないため、再読み込みや画面を閉じてもログアウトします。

## 7. 主な仕様

- 終わりかた：**時間で練習**（3分（初期）・5分・10分）または **問題数で練習**（25問・50問。時間の制限なし）。一時停止なし。途中終了は可能（完走記録・正式ランクには使いません）。
- 練習画面では「準備ができたら、スペースキーを押してスタート」と表示し、スペースキーかスタートボタンで始めます（待っている間は時間を数えません）。
- ローマ字のお手本：ヘボン式（初期）／訓令式。ガイドに出す打ち方を選ぶだけで、どちらの正しい打ち方でも入力できます。
- ローマ字入力の結果画面に、ミスした問題の詳細（ミスした位置・押したキー・回数・かかった時間・正確率）を表示します（クラウドには保存しません）。
  時間は開始時刻からの経過で測るため、タブを切り替えても延長されません。
- 速さの単位：ローマ字は「正しい打鍵数／分」、文章は「正しい日本語文字数／分」。
- 正確率：ローマ字 ＝ 正しい打鍵 ÷（正しい打鍵＋ミス打鍵）×100、文章 ＝ 正しく受理した文字 ÷（正しく受理した文字＋累積の誤確定文字）×100。入力ゼロは「—」・「未判定」。
- 24段階ランク（S＋〜G−）。速さと正確率の両方を満たす最も高いランク。アプリ独自の基準で、検定合格などを保証するものではありません。
- 正式ランクは「時間で練習」の「標準問題」を時間いっぱいまで練習したときだけ。問題数で練習したときは参考ランク。桜モード・難易度を選んだ練習・追加教材は「参考ランク」。
- 記録は「種類・時間・入力方法・問題の種類・テーマ・難易度・問題セットの版」ごとに分け、異なる条件の自己ベストを混ぜません。
- 「練習の記録」（ホーム・結果画面から）：新しい順の一覧（PC は表、スマートフォンはカード）と、同じ条件の成長グラフ（速さ・正確率、直近5回の平均）、自己ベスト、最初の5回と最近の5回の比較。対象は直近100回分で、途中終了はグラフ・平均・自己ベストから除きます（docs/scoring.md）。

- **検定モード**（v1.1.0）：左にお手本（文章・画像・PDF）、右に白紙の A4 用紙。標準10分のほか3分・5分・時間制限なし。確定済みの文章だけを採点し（変換中の文字は数えません）、置換・挿入・脱落を考えた対応付けでミス数を出します。得点文字数＝入力文字数−ミス数×段階の減点。標準10分を完了して基準以上なら「目安達成」（公式検定の合格ではありません）。記録はタイピングの記録とは別に保存し、ランクには使いません。

- **ゲームモード**（v1.2.0）：「サクラダファミリアを完成させよ」。工事の進み具合（ゲージ・完成率・完成まであと○文字（読みの文字数）・工程名）を常に表示。記録タイム＝入力時間＋ミス回数×5秒、ゲーム内の完成年＝1882＋floor(記録タイム÷2秒)。標準コース（約1800打鍵）・短縮コース（標準の約半分・約950打鍵。v1.3.0）。PC・Surface では一画面で遊べる配置（v1.3.1：建物と文を同じ大きさの枠で左右に並べ、その下に大きなキーボードと指のガイド）、ミスの効果音（「音」の設定に従う）と「＋5秒」の表示、完成記念画像（PNG）の保存。記録はタイピング・検定とは別に保存し、ランクには使いません。
- **桜ガーデン**（v1.4.0）：短い文章500文から1回5・10・20問。1問ごとに水1・花びら1、読みのかな20文字ごとに水1。苗木 → 若木 → つぼみ → 満開（最初の無料のソメイヨシノは水20、ほかは水50で満開）。お店で通常8種類の苗と飾り5種類を花びらと交換、1つの庭に桜3本・飾りはマス目に配置、累計150問・350問で庭が増えます。図鑑・持ちもの・庭の画像の保存。くわしくは [docs/garden.md](docs/garden.md)。
- **ボウイの爆弾遊戯**（v1.5.0）：4段階 × 20問（単語3段階・文章1段階）。爆弾が手を離れた瞬間に出題、早く解除するほど高得点（単語最大10点・文章最大20点、最高1000点）、ミスは減点なし、被弾でその場で終了（ゲームオーバーの煽り画像は10パターンからランダム。v1.5.1）。各段階の10問目のあとに加速のカットイン。このモードの「ん」は NN、「づ」は DU・ZU のどちらでも可。選択時にタイトルコールと白・黒の画面の切り替え。ハイスコアはこの端末にプロフィールごとに保存。くわしくは [docs/bowie.md](docs/bowie.md)。

### 検定モード：先生が問題を追加して配布する（概要）

1. 「検定モード」→「先生の追加問題を管理する」→「問題を追加する」。
2. 問題名・段階・制限時間を決め、お手本の画像（PNG・JPEG・WebP、プリントの写真も可）か PDF を選ぶ。PDF は使うページと順番を選ぶ。
3. プレビューで確かめ、採点用の正解文を入力・貼り付け（文字情報のある PDF は「PDF から文字を取り出す（補助）」も使えます）。読み順やタイトルなどを確認して「正解文を確認済み」にする。または「採点なし」を選ぶ。
4. 「この端末に保存する」→「生徒用プレビュー」で確認。
5. ほかの端末で使うときは、問題に印を付けて「教材パックで書き出す」→ 生徒の端末の「検定モード → 先生の追加問題 → 教材パックを読み込む」。**この端末に保存しただけでは、ほかの端末には届きません。**

くわしい手順・採点の規則・うまくいかないときの対処は [docs/exam.md](docs/exam.md)。

採点とランクの詳細は [docs/scoring.md](docs/scoring.md)、ローマ字の対応表は [docs/romaji-table.md](docs/romaji-table.md)、問題データは [docs/questions.md](docs/questions.md)。

## 8. 検証（テスト）

| コマンド | 内容 |
|---|---|
| `npm test` | ゲームの進行（6本の物語をヘボン式・訓令式で最後まで入力、別の打ち方、進み具合・工程・完成年）・ゲームの記録の保存と検証、ローマ字判定・文章入力の採点（IME・誤変換・重複加算なし）・ランク境界・計時・出題・初期問題の検証、検定モードの採点（置換・挿入・脱落・未入力の末尾）・収録30問・端末保存・教材パックなど（自動テスト） |
| `npm run test:db` | データベースの権限テスト（一時的な PostgreSQL に SQL を適用し、生徒・教員の役割で他人の記録が見えないことなどを確認）。PostgreSQL 15 以上が必要 |
| `npm run test:e2e` | 実際のブラウザ（Chromium）での画面テスト。PC・タブレット・スマートフォンの幅、サブディレクトリ配信、IME の変換（CDP で再現）、ログイン〜保存失敗〜再送〜ログアウト（通信はモック） |
| `npm run validate:questions` | 初期問題の重複・読み・使えない文字・文字数・よく似た問題の検出 |
| `npm run check:readings` | 形態素解析の辞書（kuromoji）で読みを照合し、食い違いを一覧にする |
| `npm run typecheck` | 型チェック |

実機でしか確認できない項目（Windows の日本語 IME、iPad Safari など）は、[docs/manual-checks.md](docs/manual-checks.md) に手順があります。

## 9. フォルダーの構成

```
src/core/          判定・採点・ランク・計時・出題のロジック（画面から独立。テストあり）
src/data/          初期問題（questions/*.json）、検定モードの収録問題（exam/exam_problems.json）、端末の保存（examStore.ts）・教材パック（examPack.ts）・PDF（pdf.ts）、Supabase との接続（cloud.ts）
```

## 10. アプリのアイコン

`assets/brand/sakura-type-original.png`（提供された「桜打／SAKURA TYPE」の画像）から、`npm run icons`（ImageMagick が必要）で作っています。
縮小のみで、切り取り・引き伸ばし・描き直しはしていません。

- `public/icons/favicon.ico`（16・32・48px）、`favicon-32.png`、`apple-touch-icon.png`（180px）、`icon-192.png`、`icon-512.png`
- `icon-maskable-192.png` / `icon-maskable-512.png`：maskable 用の別画像。画像全体を56%に縮小し、元画像の地色で余白を付けて、桜と文字が安全領域に収まるようにしています
- アプリ名「桜打 — SAKURA TYPE」、ホーム画面用の短い名前「桜打」（`public/manifest.webmanifest`）
